Follow one request

Three things I shipped, followed from the screen down to the row and back. Pick one.

A coin purchase

  1. The screen

    A player taps a coin pack. The client never writes a balance, it only asks for one.

  2. The receipt

    Play returns a purchase token to the Cloud Function. The game does not get to keep it.

  3. Google

    The function asks Play whether that token is real, mine, and not already spent.

  4. The ledger

    A Firestore transaction credits the coins and records a hash of the token. Run it twice, nothing doubles.

  5. The screen again

    The game re-reads its balance and shows what it now owns.

A phone that lies about a purchase cannot move a single coin.

A chart page

  1. The crawl

    A daily job reads public store pages for 1,935 apps in 20 storefronts.

  2. The rows

    Each rank lands as a row: chart, storefront, position, rating, price.

  3. The build

    One build turns those rows into 1,935 app pages, 40 chart pages and 20 country hubs. Static HTML, no database behind the request.

  4. The edge

    A Cloudflare Worker serves the files. Nothing renders when you load the page.

  5. The index

    IndexNow is given only the URLs whose content actually changed that morning.

Nothing is rendered when you open the page. It was rendered this morning.

A checkout

  1. The action

    A pre-order opens and the burst arrives at once.

  2. The gate

    A queue holds the crowd in front of the storefront instead of letting it hit the database.

  3. The order

    The Remix action writes to Vendure, which checks stock and price where they live.

  4. The payment

    The provider confirms, Vendure records the transaction, the queue moves on.

  5. The email

    A transactional email leaves with the order number and the album it bought.

The queue takes the hit so the database does not.
